## 0. v2.0 变更说明

v1.0 是"基于当前代码界面盘点"的照抄式需求，核心原则是**不得删减现有能力**。该前提已随两件事失效：

1. 项目已完成模块化，产品已决定**全 App UI 重做、旧 UI 整体删除**（Phase 10）。既然旧界面不再是迁移目标，就没有理由继承它的开关堆、路由绕行和界面逻辑。
2. 重设计画板墙（55 个画板）已导入并自带五条设计契约，其中"设置路由重排（九个平级入口改三组）""主题收敛为日光/夜墨/跟随系统 + 强调色种子""正文纸色独立于 App 主题"都是**已经拍板的重思考**，v1.0 与之冲突。

v2.0 的变化：

| 变化 | v1.0 | v2.0 |
| --- | --- | --- |
| 底线 | 不得删减现有能力，逐控件等价 | **能力等价、界面自由**：等价的单位是"用户任务"，不是控件；开关可删、页面可并、路由可改 |
| 依据 | 界面截图式盘点 | 三份代码审计（设置项全量、导航路由、界面逻辑一致性）+ 画板墙契约 |
| 新增 | — | 设计哲学（§2）、现状病灶清单（§3）、新信息架构（§4）、开关与设置治理（§5）、统一交互模板（§6）、旧功能—新去向映射表（§17） |
| 删除保护 | 无条件保留 | 每一次删改必须在映射表登记处置：**保留 / 合并 / 预设化 / 删除（附理由）** |

## 1. 产品定义与设计目标

这是一个以"本地书架 + 多书源检索 + 文字/漫画/听书阅读 + RSS + 可编程规则"为核心的高级阅读器。用户既包括只想安静阅读的普通读者，也包括维护书源、替换规则、TTS、备份与 Web 服务的高阶用户。

设计应同时达成：

1. **读得沉浸**：正文与漫画阅读是最高优先级场景，操作默认隐退，控制在需要时快速出现。
2. **找得明白**："搜索书""发现书""书架内找书""RSS 阅读"明确区分，降低迷失感。
3. **管得住**：书源、规则、缓存、备份、AI、Web 服务等高阶能力分层呈现，不淹没普通用户，也不深埋。
4. **状态可信**：网络加载、搜索进度、下载缓存、AI 流式生成、备份恢复均可见、可取消、可重试。
5. **可个性化**：主题、字体、阅读排版可配置——但个性化通过**少量高杠杆选项 + 预设**表达，不通过开关堆表达。
6. **做得干净**（v2.0 新增）：这是十年功能累积后的一次系统性减法。设计的职责不只是把旧功能画得更好看，而是判断每个开关、每条路由、每种交互模式**该不该继续存在**。

## 2. 重设计哲学

六条原则，全部可验收。

**P1 能力等价、界面自由。** 等价的单位是用户任务（"把这本书换个来源"），不是控件（"换源对话框里的校验作者开关"）。一个任务可以换入口、换形态、换步骤，但不能变得不可完成或明显更难发现。

**P2 开关必须证明自己该存在。** 每个用户可见开关/选项过四问，答不好即删或预设化：

1. 有没有一个对绝大多数人正确的默认值？有 → 用默认值，开关删。
2. 它是不是在弥补某个设计缺陷？是 → 修设计，开关删（例：`bookshelfSearchActionDirectToSearch` 存在只因搜索按钮语义不清）。
3. 它影响的是"行为"还是"品味"？品味类（圆角、边框、模糊、图标行列数）归主题预设，不做独立开关。
4. 它保护的是少数硬需求（无障碍、墨水屏、物理按键）吗？是 → 保留，但收进对应专区，不占常规视线。

验收目标：用户可见设置控件较现状（约 350+，见 §3.1）**压缩 50% 以上**；每个保留的开关在映射表里写得出四问答案。

**P3 一个功能一个家。** 每个功能恰有一个规范页面/规范入口；上下文中允许快捷方式，但快捷方式必须是**到同一目的地的深链**，不是第二套 UI（现状反例：备份在首页卡片与设置页是两套操作面；换源有 Compose Sheet 和 View Dialog 两套）。同一开关不得在两页同时出现。

**P4 模板化。** 高级列表、导入审核、选择态、搜索、弹层五大交互模板（§6）全 App 共用；任何页面不得自造同类交互的变体。

**P5 预设优先。** 面向"品味"的参数堆（阅读菜单外观 30+ 项、页眉页脚 12 控件、漫画面板 45 项、书架显示 40 项）改为 2–4 个预设 + 一个集中式"自定义"逃生舱（P2 优先级），把滑杆从主路径上清走。

**P6 状态可信、Toast 降级。** 长任务必有持续进度、取消与完成摘要；Snackbar 承载可撤销轻反馈；Toast 不承载唯一重要信息（现状 201 处 `toastOnUi` 是主要反馈手段，必须系统性替换）。

## 4. 新信息架构

### 4.1 一级导航

底部导航（手机）/ 导航轨（平板）。项目与顺序仍可由用户配置（3–5 项），但**默认结构与职责**重新定义：

| Tab | 职责（重新定义） | 关键变化 |
| --- | --- | --- |
| 首页（可隐藏） | **个人聚合**：继续阅读、阅读目标与统计摘要、备份状态提醒、精选发现模块 | 模块流是"发现"数据的转发视图，点击一律进入发现分类页（同一路由），首页不再持有平行的内容浏览系统（解 N8）。备份卡片降级为**状态 + 深链**，不再是第二套备份操作面（P3）。 |
| 书架 | 我的书。分组、排序、批量管理 | 搜索按钮**只做书架内过滤**；空结果给出"全网搜索『关键词』"的显性跳转。删除行为切换偏好（解 N7、四问 2）。 |

### 4.4 路由与返回栈规范

1. **单 Activity**：全部界面为 Navigation 3 路由。现存 20 个业务 Activity 中 17 个已是 Compose 宿主，无技术理由保留；8 个入口型 View Activity（文件关联、扫码、验证码、URL 确认、在线导入）收敛为一个透明 EntryActivity + 路由分发（解 N5、N6、d8）。
2. **打开书籍单机制**：`openBook(route)` 一种实现，所有入口（书架、首页、阅读记录、导入、文件关联、通知）同一转场与返回语义（解 N4）。
3. **禁止内部 Activity Result**：阅读器↔目录/替换规则/详情之间用路由返回值/共享状态，不再穿 Activity 边界（解 N5、N6）。
4. **弹层不建私有导航栈**：BottomSheet 内嵌套 ≤2 层；超过的改为路由页（首页模块管理 6 页私有栈改为真路由，解 N9、L3）。
5. **隐藏手势只做加速器**：长按/双击承载的功能必须同时有显性入口（解 N10）。
6. **深度预算**：高频任务（继续阅读、搜书、切主题、换源）距一级页 ≤2 次点按；任何设置 ≤3 层；任何功能 ≤4 层（解 N11）。

### 4.5 主要任务流

```text
启动 → 首页 / 用户设定的默认一级页
        ├─ 继续阅读 → 文字阅读器 / 漫画阅读器 / 听书播放器（单机制 openBook）
        ├─ 发现 → 搜索（常驻框）→ 结果 → 书籍详情 → 加入书架 / 阅读
        │        └─ 发现分类 → 书单 → 书籍详情（首页模块点击也汇入此流）
        ├─ 书架 → 书组 → 书籍详情 / 阅读 / 批量管理
        ├─ 订阅 → 分类文章 → 网页/阅读模式文章
        └─ 我的 → 主题、书签、记录与统计、AI 对话、源与规则、设置、关于
```

### 4.6 全局状态规范

每个网络或数据页面必须设计：首次骨架屏、下拉刷新、加载更多、空状态（解释原因 + 下一步）、局部失败/整页失败、离线、进行中、成功/失败提示、危险操作二次确认。长列表保留滚动位置；搜索、书架编辑、阅读器切前后台不丢上下文。

## 6. 统一交互模板

### 6.1 高级列表（源与规则）

一个模板实例化全部 8 类列表。**基线能力**（人人都有）：搜索、多选、启停、拖拽排序、本地/网络导入、导出/上传、编辑、删除确认。**可选插槽**（按对象声明）：分组、置顶/置底、排序方式、可用性检查（含并发/超时配置与逐项进度、可取消）、调试入口、内置规则导入、二维码导入、导入冲突策略。现状"书源特权、其余降级"（L7）由插槽声明取代；措辞与图标全局统一（全选/反选/启用/置顶）。

### 6.2 导入审核（单一流程，解 L8）

应用内粘贴/文件/链接、外部 `legado://` 链接、文件关联三条路径汇入**同一个审核面板**：全选、按状态筛选（新增/更新/冲突）、逐项编辑、冲突策略（保留原名/分组/启用状态、指定新分组）——冲突策略对所有规则类型开放，不再是书源专属。导入来源选择（系统文件/应用目录）并入面板首步，不再单独弹 `FilePickerSheet`（L9）。

### 6.3 选择态（解 L10）

统一底部浮动条：`[全选] [反选] [已选 N] … [主操作] [更多 ▾]`。主操作按对象类型固定：书=下载/移组（书架场景）、源与规则=启停、缓存=删除缓存。**删除一律进"更多"+ 二次确认**，不做主按钮。次级操作 >5 项时分组呈现，长任务类（检查可用性）标注为长任务。书架与其余页面同一套语言。

### 6.4 搜索（解 L6）

只允许两种形态：

1. **列表内联过滤**：顶栏搜索态（书架、目录、各列表页、RSS 文章——RSS 的 Sheet 输入取消）。
2. **全局搜索页**：发现 tab 常驻框进入；范围选择、进度（已处理源/总源）、单源错误、结果布局设置齐备。

正文搜索改为**阅读器内覆盖层**：不跳整页路由、不经全局单例回传；结果导航收敛为单一控件（当前 N/M + 上一条/下一条）。换源面板内的搜索复用全局搜索的构件与状态语言。

### 6.5 弹层分层（解 L9）

| 层 | 用途 | 禁止 |
| --- | --- | --- |
| Dialog | 确认、单值输入、风险说明 | 可滚动多选列表 |
| BottomSheet | 上下文选择、轻设置（≤2 层嵌套，实时预览） | 私有导航栈、单滑杆独占一个 Sheet |
| 路由页 | 浏览、编辑、多步流程、长列表管理 | — |

同类操作全 App 同层（书组管理、换封面、日志、文件选择各自只有一套实现）。

### 6.6 长任务与反馈（解 L12）

书源检查、批量下载、批量换源、备份恢复、AI 生成、导入共用一种"进行中"语言：持续进度 + 逐项状态 + 取消 + 完成摘要。Snackbar 用于可撤销轻反馈；Toast 仅作纯提示冗余，不承载唯一重要信息。

## 18. 关键交互与异常要求

### 18.1 删除、覆盖和不可逆操作

- 删除书籍区分"仅移出书架"与"同时删除本地文件"；默认选项不可误删。
- 删除源、规则、主题、缓存、TTS 文件、备份恢复、数据库瘦身均说明对象名称/数量与影响。
- 导入同名对象、换源冲突、恢复配置给出保留/覆盖/跳过/新建选择（统一在 §6.2 冲突策略中表达）。
- 长任务遵守 §6.6：持续进度、取消、完成摘要。

### 18.2 权限与外部能力

| 能力 | UI 要求 |
| --- | --- |
| 存储/目录 | 真正使用前解释用途；拒绝后提供重新授权或替代路径。 |
| 相机 | 扫码首次请求；拒绝给粘贴/相册替代。 |
| 通知 | 在开启下载/朗读/缓存等能力时请求，不启动即请求。 |
| 后台/电池优化 | 仅 Web 服务、长下载、朗读需要时提出，浅显说明影响。 |
| 浏览器/分享/文件打开 | 显示将打开的对象；外部返回后恢复滚动位置与任务状态。 |

### 18.3 设计验收清单

1. 所有 P0/P1 画板及关键抽屉/确认/错误状态交付；深浅色、大字号可读不溢出；手机与平板断点齐备。
2. 文字阅读器覆盖"纯阅读、菜单层级、搜索、选区、朗读、样式、异常"，且菜单层级符合 §11.1（无假 Tab、无私有栈、嵌套 ≤2）。
3. 五大交互模板（§6）各有一份规范稿，所有相关页面标注引用模板而非自绘变体。
4. 每个保留的开关有四问答案；同一开关不出现在两页；每个功能只有一个规范入口。
5. 无网络、无数据、无权限、加载中、部分失败、取消、成功/失败均有方案；Toast 不承载唯一重要信息。
