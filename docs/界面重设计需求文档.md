# 阅读（Legado MD3）界面重设计需求文档

> 版本：v1.0（基于当前代码界面盘点）  
> 平台：Android 手机优先；同时适配平板、横屏、折叠屏。  
> 用途：供产品设计、视觉设计和交互设计建立信息架构、流程与高保真稿。  
> 原则：本次是视觉与交互重设计，**不得删减现有能力**；如需合并入口，必须保留等价的可发现路径。

## 1. 产品定义与设计目标

这是一个以“本地书架 + 多书源检索 + 文字/漫画/听书阅读 + RSS + 可编程规则”为核心的高级阅读器。用户既包括只想安静阅读的普通读者，也包括维护书源、替换规则、TTS、备份与 Web 服务的高阶用户。

设计应同时达成：

1. **读得沉浸**：正文阅读和漫画阅读是最高优先级场景，操作默认隐退，信息与控制在需要时快速出现。
2. **找得明白**：把“搜索书”“发现书”“书架内找书”“RSS 阅读”明确区分，降低功能密度带来的迷失感。
3. **管得住**：书源、规则、缓存、备份、AI、Web 服务等高阶能力分层呈现，既不淹没普通用户，也不能被深埋。
4. **状态可信**：网络加载、书源搜索进度、下载/缓存、AI 流式生成、备份/恢复等均必须可见、可取消、可重试。
5. **可个性化**：主题、字体、导航、封面、阅读排版和阅读菜单均可配置；设计系统需预留这些变量。

### 1.1 设计边界

| 范围 | 要求 |
| --- | --- |
| Android 主应用 | 本文全部页面与弹层均需提供设计稿；优先 Material 3 语义和现有 Material 3 主题能力。 |
| 手机 | 基准宽度 360–430 dp；单手触达优先；核心触点不小于 48 dp。 |
| 平板/横屏/折叠屏 | 宽屏采用导航栏/导航轨 + 双栏或三栏：书架/列表在左，详情/内容在右；不要单纯放大手机布局。 |
| 深色、动态色与自定义主题 | 所有关键页面必须至少交付浅色、深色、长文本/大字号状态；颜色不能只依赖品牌固定色。 |
| 嵌入式网页与系统页面 | WebView、文件选择、权限、浏览器/分享等需设计宿主态与返回路径；系统原生选择器本身不重画。 |
| 不在本次强制范围 | 后端协议、书源规则语法、数据库结构、阅读排版算法不重做；UI 可优化其编辑与反馈方式。 |

### 1.2 核心对象与术语

| 对象 | 用户可见含义 | 主要出现位置 |
| --- | --- | --- |
| 书/书架书籍 | 已加入书架的文字书、音频书或漫画书 | 首页、书架、阅读器、书籍详情 |
| 搜索书籍 | 来自书源、尚未或已加入书架的检索结果 | 搜索、发现、首页模块、相关书籍 |
| 书源 | 提供搜索、详情、目录、正文和发现内容的规则化数据源 | 书源管理、编辑、调试、登录 |
| RSS 源 | 提供订阅分类和文章的数据源 | RSS、RSS 源管理、文章页 |
| 规则 | 替换/净化、TXT 目录、词典、高亮标签等可导入导出的配置 | “我的—规则”、阅读器、各管理页 |
| 书组 | 书架的分组、文件夹或筛选维度 | 书架、书组管理、批量操作 |

## 2. 信息架构与全局导航

### 2.1 一级导航

底部导航在手机显示；平板/横屏优先改为左侧导航轨。导航顺序、显隐、图标、默认首页均允许用户配置，因此视觉上必须支持 3–5 个项目及项目重排。

| ID | 一级页 | 主要内容 | 关键入口 |
| --- | --- | --- | --- |
| M-01 | 首页 | 阅读进度、最近阅读、阅读目标、来源首页模块、备份捷径 | 继续阅读、书籍详情、来源首页、备份/恢复 |
| M-02 | 书架 | 书组、书籍列表/网格、批量管理 | 阅读、搜索、导入、缓存、书组管理 |
| M-03 | 发现 | 已启用书源的发现分类 | 分类书单、书源编辑/登录/搜索 |
| M-04 | RSS | RSS 源入口与订阅内容 | 分类文章、文章阅读、RSS 源管理 |
| M-05 | 我的 | 服务、规则、工具和关于 | 设置、书源、规则、书签、记录、文件管理 |

全局顶栏需容纳：当前页标题、搜索（按场景）、AI 对话、设置/更多；阅读器使用独立沉浸式导航，不能沿用主框架顶栏。

### 2.2 主要任务流

```text
启动 → 首页 / 用户设定的默认一级页
          ├─ 继续阅读 → 文字阅读器 / 漫画阅读器 / 听书播放器
          ├─ 搜索 → 选择范围 → 搜索结果 → 书籍详情 → 加入书架 / 阅读
          ├─ 书架 → 书组 → 书籍详情 / 阅读 / 批量下载
          ├─ 发现 → 书源分类 → 书单 → 书籍详情
          ├─ RSS → 分类文章 → 网页/阅读模式文章
          └─ 我的 → 设置、书源、规则、备份、文件、统计、关于
```

### 2.3 全局状态规范

每个网络或数据页面必须设计以下状态，不能只交付“有数据”稿：首次骨架屏、下拉刷新、加载更多、空状态（解释原因 + 下一步）、局部失败/整页失败、离线状态、进行中状态、成功/失败提示和删除/覆盖的二次确认。长列表需要保留滚动位置；搜索、书架编辑和阅读器切换前后台后不得丢失当前上下文。

## 3. 视觉与交互系统需求

### 3.1 视觉基调

- 关键词：安静、纸感、可靠、精致但不花哨。阅读内容永远高于装饰。
- 封面图是高密度视觉资产：封面缺失、加载中、失败、书源封面与用户自定义封面均需有统一规则。
- 支持动态色、12 个预置主题、用户种子色/调色板以及透明主题；设计令牌需表达 `surface / surfaceContainer / outline / primary / error / scrim` 等语义，而非把具体色写死。

### 3.2 字体与可访问性

- 应支持系统字体、应用字体文件、阅读正文字体、标题字体、页眉页脚字体分别设置。
- 常规 UI 最小正文建议 14sp；高密度规则编辑器可降至 12sp，但不可低于可读下限。所有文字应允许系统字体缩放。
- 颜色对比满足 WCAG AA；错误、加载、禁用、选中不能仅以颜色区分。
- 为封面、书签、下载、播放、收藏、源状态等图标提供内容描述；长按操作要有可替代的显性菜单入口。

### 3.3 通用组件清单

| 组件 | 设计要求 |
| --- | --- |
| 顶部应用栏 | 标准、可折叠大标题、搜索态、选择态四种；返回键和危险操作位置固定。 |
| 底部导航/导航轨 | 支持项目重排、隐藏、动态图标与徽标；书架可带书组快速菜单。 |
| 书籍卡片 | 网格、紧凑网格、列表、带分组网格四类；显示封面、书名、作者、进度/最新章、更新/下载/错误状态。 |
| 来源/规则列表项 | 标题、分组/域名、启用开关、能力标签、排序/多选状态、长按菜单。 |
| 选择态底栏 | 全选、反选、数量、启用/停用、分组、下载、导出、删除等按上下文组合。 |
| 筛选抽屉 | 多选组、来源、类型、排序；应用/重置/当前筛选摘要必须清晰。 |
| 底部抽屉 | 承载不打断上下文的选择和设置；高度可滚动，危险操作用确认对话框。 |
| 表单 | 规则和服务地址为长文本场景：多行编辑、粘贴、清空、校验错误、帮助、示例、保存未完成提示。 |
| 反馈 | Snackbar 用于可撤销轻反馈；进度面板用于可取消长任务；Toast 不承载唯一重要信息。 |

### 3.4 自适应布局

| 窗口级别 | 推荐结构 |
| --- | --- |
| 紧凑（手机竖屏） | 单栏，底部导航，抽屉/全屏详情。 |
| 中等（横屏手机、折叠展开） | 左侧导航轨；书架、RSS、来源管理可列表—详情双栏。 |
| 扩展（平板） | 导航轨 + 书组/来源栏 + 内容栏；阅读器可“目录/正文”并列，设置可分类栏 + 设置详情。 |

## 8. 文字阅读器（P0，需单独完整交付）

## 15. 关键交互与异常要求

### 15.1 删除、覆盖和不可逆操作

- 删除书籍必须区分“仅移出书架”和“同时删除本地源文件”；默认选项不可造成误删。
- 删除来源、规则、主题、相册、缓存、TTS 文件、备份恢复和数据库瘦身都必须有对象名称/数量及影响说明。
- 导入同名书源/规则/书籍、换源冲突、恢复配置时必须给出保留、覆盖、跳过或新建的选择。
- 长任务（书源检查、备份/恢复、导入、下载、AI 分组/生成）需避免用户误以为卡死：持续进度、取消和完成摘要是必需品。

### 15.2 权限与外部能力

| 能力 | UI 要求 |
| --- | --- |
| 存储/目录 | 在真正选择/导入/备份前解释用途；被拒绝后提供重新授权或可用替代路径。 |
| 相机 | 二维码扫描首次请求；拒绝时显示手动粘贴/从图片选择（如可用）的替代入口。 |
| 通知 | 下载、朗读、缓存等服务所需通知权限应在开启相关能力时请求，而非启动即请求。 |
| 后台运行/忽略电池优化 | 仅在 Web 服务、长下载、朗读等需要时提出，并用浅显语言说明影响。 |
| 浏览器/分享/文件打开 | 显示将要打开或分享的对象；外部返回后恢复原来的滚动位置与任务状态。 |

### 15.3 设计验收清单

1. 五个一级页、本文所有 P0/P1 画板、所有关键抽屉/确认/错误状态均已交付。
2. 文字阅读器完整覆盖“纯阅读、主菜单、搜索、选区、朗读、样式、异常”而不只是正文页。
3. 书源、规则、RSS 三类专家列表均有批量、多选、导入审核和错误/进度设计。
4. 手机与平板均有布局规则；深色、浅色、大字体可读且不溢出。
5. 无网络、无数据、无权限、加载中、部分失败、取消、成功/失败提示有对应方案。
6. 所有危险操作可辨识、可取消、影响明确；所有长任务可见进度且可恢复。
7. 新方案保留当前入口语义：用户仍能从书架、书籍详情、阅读器、我的和外部文件/链接到达相应功能。

## 16. 建议交付物与优先顺序

第一批先完成 P0：主框架、首页、书架、搜索、书籍详情、目录、文字阅读器、我的和设置主页。第二批完成 P1：发现、RSS、导入/缓存、书源/RSS 管理、规则、备份、TTS、阅读统计。第三批完成 P2：主题深度定制、AI 自动分组、调试、实验室、崩溃与低频关联入口。

建议最终文件包含：信息架构图、任务流、设计令牌、核心组件库、每个 ID 的浅/深色画板、关键状态稿、手机/平板断点稿、交互动效说明，以及一份“旧功能—新入口”映射表。开发交接时以本文件 ID 作为页面和验收用例编号。
